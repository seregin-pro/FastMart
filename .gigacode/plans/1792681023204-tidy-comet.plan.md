# FastMart — Spec-Driven Development Specification

## 1. Обзор проекта

**FastMart** — интернет-магазин продуктов питания, реализованный как микросервисное приложение на Spring Boot + React.

### 1.1. Стек технологий

| Компонент | Технология |
|---|---|
| Backend | Spring Boot 4.0.2, Java 25, Spring Security, Spring Data JPA |
| Frontend | React 19, Vite 7, Mantine |
| Базы данных | PostgreSQL 18 |
| Кэширование | Redis (product-service) |
| Аутентификация | JWT (jjwt 0.13.0, HS512) |
| Контейнеризация | Docker, Docker Compose |
| Сборка | Gradle (Kotlin DSL) |

### 1.2. Архитектура микросервисов

```
┌─────────────────────────────────────────────────────────┐
│                    Frontend (React)                      │
└──────────────────────────┬──────────────────────────────┘
                           │ HTTP/REST
               ┌───────────┴───────────┐
               │   API Gateway (TODO)   │
               └───────────┬───────────┘
            ┌──────┬──────┼──────┬──────┐
            ▼      ▼      ▼      ▼      ▼
       ┌────┐ ┌────┐ ┌────┐ ┌────┐ ┌────┐
       │  Auth (+User)  │ │Prod│ │Cart│ │Ord │ │Pay │
       │     SVC        │ │SVC │ │SVC │ │SVC │ │SVC │

         │      │      │      │
```

## 2. Текущее состояние сервисов

### 2.1. auth-service ✅ (Рабочий)

**Реализовано:**
- Регистрация (`POST /api/auth/signup`)
- Авторизация (`POST /api/auth/signin`) → JWT token
- JWT Filter + Security Config
- Роли: ROLE_USER, ROLE_ADMIN
- Admin endpoint: `POST /api/admin/add_role`

**Баги и проблемы:**
- Дублирование DTO: `dto/`, `request/dto/`, `response/dto/` — `dto/` мёртвый код
- `spring.application.name=productservice` (ошибка копипасты)
- Нет Dockerfile (есть в корне, но настроен некорректно)
- Секрет JWT захардкожен: `your-secret-key-here-change-in-production`
- CORS: `allowedOrigins: ["*"]` (безопасно, но нужно настроить под конкретные домены)
- `JwtAuthenticationEntryPoint` возвращает misleading JSON `{username, password}`

### 2.2. product-service ✅ (Рабочий)

**Реализовано:**
- CRUD для Product, Category, Manufacturer
- Redis кэширование (findById, save, delete)
- Пагинация (ProductFilter, CategoryFilter, ManufacturerFilter)
- ManyToMany Product ↔ Category
- GlobalExceptionHandler
- Seed data: 1000 продуктов, 5 производителей, 5 категорий

**Баги и проблемы:**
- Опечатка в пакете: `repositary` вместо `repository`
- Нет Spring Security
- Нет Dockerfile
- `@JoinColumn` на `Long parentId` в Category — некорректно для JPA
- `spring.sql.init.mode=always` + `ddl-auto=update` — конфликтующие подходы

### 2.3. cart-service ✅ (Рабочий)

**Реализовано:**
- CRUD для ShoppingCart и CartItem
- `create_shopping_cart`, `add_product_to_cart`, `remove_cart_item`, `clean_cart`
- Увеличение/уменьшение количества товаров
- Проверка наличия корзины пользователя

**Баги и проблемы:**
- Нет Spring Security
- Нет Dockerfile
- `System.out.println` вместо логирования в `decreaseProductQuantityFromCart`
- `presentCartItem.equals(null)` вместо `== null` (anti-pattern)
- Нет DTO для ответа `getAllCartItems` — возвращает сырой entity

### 2.4. order-service ⚠️ (Полурабочий)

**Реализовано:**
- Создание заказа (`POST /api/order/create_order`)
- Отмена заказа (`POST /api/order/cancel_order`)
- Получение заказов (`POST /api/order/get_all_orders`)
- Сущности: ProductOrder, OrderItem

**Баги и проблемы:**
- SecurityConfig полностью закомментирован
- Лишний `BCryptPasswordEncoder` bean в main class
- Нет глобального exception handler
- Нет валидации входных данных
- `cancelOrder` — NPE risk при `findById.orElse(null)` без null-check
- Нет Dockerfile
- `@Autowired` вместо constructor injection

### 2.5. user-service ⚠️ → auth-service (Консолидация)

**Решение:** user-service консолидируется в auth-service. Auth-service становится единым источником правды о пользователях.

**Реализовано в user-service:**
- Создание пользователя (`POST /api/user/create-user`)
- Получение информации (`POST /api/user/get-user-info`)
- Создание/обновление адреса (`POST /api/user/create-update-address`)
- Сущности: User, Address

**Баги:**
- **Критический баг:** `address.setState(request.getPin())` вместо `request.getState()`
- Конфликт драйверов: MySQL в properties, PostgreSQL в build.gradle.kts
- Eureka client config, но нет Eureka server
- Нет Spring Security
- Нет Dockerfile
- `@Autowired` вместо constructor injection

**План консолидации:**
- Перенести сущности User и Address в auth-service
- Перенести endpoints: `GET /api/users/{id}`, `PUT /api/users/{id}`, `GET /api/users/me`
- Удалить user-service как отдельный микросервис
- Обновить docker-compose (убрать user-db, использовать auth-db)

### 2.6. frontend-react ❌ (Пустой)

**Реализовано:**
- Базовый Vite + React 19 проект

**Отсутствует:**
- Роутинг (react-router)
- HTTP-клиент (axios/fetch wrapper)
- Состояние (context/redux/zustand)
- UI-компоненты
- Любая интеграция с backend
- Стилизация
